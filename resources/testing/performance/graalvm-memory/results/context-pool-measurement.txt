Reading the table:
  idle heap  = heap retained by the idle pooled contexts (after full GC) minus the heap
               before any context existed (Engine + warm-up already in place)
  exec heap  = same, after executing onMessage once in every context
  freed MB   = heap released again by invalidating the tenant's pool

Extrapolation from the 1000-context row (85 KB per executed context):
   50 mappings x 20 pooled contexts x  1 tenants =  1,000 contexts -> ~83 MB
   50 mappings x 20 pooled contexts x  5 tenants =  5,000 contexts -> ~415 MB
  100 mappings x 20 pooled contexts x 10 tenants = 20,000 contexts -> ~1661 MB
  (DEFAULT_POOL_SIZE = 20 idle contexts per mapping; the pool only grows to what
   concurrency actually asked for, so the real figure sits between the 1x and 20x rows.)
