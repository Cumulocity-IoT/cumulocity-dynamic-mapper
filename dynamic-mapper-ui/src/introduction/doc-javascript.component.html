{{ 'How to migrate' | translate }}

Smart Functions supersede Substitution as JavaScript. Instead of returning a SubstitutionResult object with individual field substitutions, a Smart Function builds and returns the complete Cumulocity target object (or an array of objects) directly — giving you full control over the output payload.
  1. Export the affected mapping using the Export action in the mapping grid. Keep the export as a reference for the JavaScript logic you need to migrate.
  2. Create a new mapping with transformation type Smart Function (JavaScript) and configure the same topic, target API, and general settings.
  3. Rewrite the JavaScript: adapt your substitution code so it builds and returns a full Cumulocity object. The Smart Function API uses function onMessage(message, context) { … return obj; }. See the Smart Functions documentation for the complete API reference and code templates.
  4. Test the new mapping using the built-in Test feature and verify it produces the expected Cumulocity format.
  5. Activate the new mapping, then delete the original deprecated mapping.
Info — Key API differences
  • Old (SUBSTITUTION_AS_CODE): Return a SubstitutionResult populated via addSubstitution(result, targetPath, new SubstitutionValue(...)). The mapper applies each substitution to the target template.
  • New (SMART_FUNCTION): Return a fully-built JavaScript object (or array of objects) from onMessage(message, context). The returned object is sent directly to Cumulocity — no template merging occurs.
  • Access the inbound payload via message.getPayload() (returns a parsed JavaScript object for JSON payloads).
  • Access device inventory data via context.getInventory(externalId, externalIdType).
  • Use context.setState(key, value) / context.getState(key) for stateful processing across messages.
