{{ 'Defining a substitution using JavaScript (deprecated)' | translate }}

JavaScript substitutions allow you to define individual field transformations directly in the mapping editor using JavaScript code.
At runtime, the JavaScript code is evaluated and copies the value to the target payload path.
Caution
The JavaScript editor is only available if you select Substitution as JavaScript (deprecated) when creating the mapping. You cannot switch between transformation types after creating the mapping.
Info
When to use JavaScript Substitutions: Choose JavaScript substitutions when you need:
  • Familiar JavaScript syntax instead of learning JSONata
  • Complex string manipulations or regular expressions
  • Mathematical calculations or date operations
  • Conditional logic that's easier to express in imperative code
For complete control over the entire payload structure, consider using Smart Functions instead.

SubstitutionValue, TYPE, and RepairStrategy

JavaScript substitutions return a SubstitutionResult populated via addSubstitution(result, key, value). The value argument must be a SubstitutionValue that declares the value, its type, a repair strategy, and whether arrays should be expanded into multiple Cumulocity objects. 
// Construct a SubstitutionValue:
// new SubstitutionValue(value, TYPE.xxx, RepairStrategy.xxx, expandArray)

const result = new SubstitutionResult();
addSubstitution(result, "source.id", new SubstitutionValue(
  payload["deviceId"],          // value to substitute
  TYPE.TEXTUAL,                 // type of the value
  RepairStrategy.DEFAULT,       // what to do when value is missing/null
  false                         // expand arrays into multiple objects?
));
return result;
TYPE enum
Describes the data type of the extracted value:
ValueDescription
TYPE.TEXTUALString value
TYPE.NUMBERNumeric value (integer or float)
TYPE.BOOLEANBoolean value (true / false)
TYPE.OBJECTJSON object — copied as-is into the target
TYPE.ARRAYJSON array — use with expandArray: true to generate multiple Cumulocity objects from one message
TYPE.IGNOREThe substitution is skipped; use for conditional mappings where you want to omit a field
RepairStrategy enum
Controls what the mapper does when the extracted value is null, missing, or an array that needs to be mapped to a scalar target field:
ValueDescription
RepairStrategy.DEFAULTUse the value as-is; if null, the target field is set to null
RepairStrategy.USE_FIRST_VALUE_OF_ARRAYIf the value is an array, take the first element for the target field
RepairStrategy.USE_LAST_VALUE_OF_ARRAYIf the value is an array, take the last element for the target field
RepairStrategy.IGNOREIf the value is null or missing, skip this substitution entirely (the target field keeps its template default)
RepairStrategy.REMOVE_IF_MISSING_OR_NULLIf the value is null or missing, remove the target field from the payload completely
RepairStrategy.CREATE_IF_MISSINGIf the target field does not exist in the template, create it with the substituted value
expandArray
When expandArray is set to true and the substituted value is an array, the mapper generates one Cumulocity object per array element. For example, a payload with three temperature readings can produce three separate measurements in a single message: 
// Payload: { "temps": [10.5, 30.0, 49.2] }
// With expandArray: true, this creates 3 separate measurements
const result = new SubstitutionResult();
addSubstitution(result, "c8y_Temp.T.value", new SubstitutionValue(
  payload["temps"],
  TYPE.ARRAY,
  RepairStrategy.DEFAULT,
  true   // expand: one measurement per element
));
return result;
